%
% Subject overview
%
Model-Based Systems Engineering (MBSE) manages the growing complexity of cyber-physical systems through a central, formalized system model \citep{incose2007mbsevision}. SysML is the established language for such models. Its most recent revision, SysML~v2, rebuilds the language on the formally grounded Kernel Modeling Language (KerML) \citep{omg-kerml}, with a textual notation and a standardized API for tool access.

%
% Concrete contribution
%
This thesis empirically evaluates the SysML~v2 modeling capabilities of LLM-based agents operating interactively on a live model inside the industrial tool Magic Systems of Systems Architect (MSoSA). A purpose-built Model Context Protocol (MCP) bridge connects the agent to MSoSA's Java Open API (plugin API) and exposes the live model state as tools. Based on the failures observed with this bare bridge, it is then extended by a harness of knowledge base, guardrails and encoded best practices intended to improve adherence to modeling conventions. The open-source Airbus Apollo~11 SysML~v2 model \citep{helle2026apollo} serves as the system under test, with the GfSE model collection \citep{gfse-models} as a smaller secondary set.

%
% Relevance
%
In a recent review of LLMs for system modeling \citep{fresemann2025review}, interactive, tool-using agents on live models do not appear as an evaluated subject. The closest work either evaluates file-based tooling only \citep{dempsey2026nativeai} or contributes an MCP framework without a capability evaluation \citep{bazzal2026mcpmbse}, and no standard benchmark for fundamental modeling tasks exists \citep{bouamra2025systemp,quast2026graphrag}. Closing this gap matters, as industry deploys agentic MBSE tooling faster than it is measured.

%
% Research Question
%
\medskip
\textbf{RQ:} \textit{Which SysML v2 modeling tasks can an LLM-based agent perform reliably in an industrial modeling environment (MSoSA) when connected through an MCP bridge, and where do its capabilities break down?}
\medskip

%
% Methodology
%
The evaluation is organized as a benchmark of six use cases on Apollo~11: \textbf{Create}, \textbf{Query}, \textbf{Patch} and \textbf{Delete} as primitives on the live model, plus \textbf{Verification} and \textbf{Validation}, distinguished according to ISO/IEC/IEEE~15288 \citep{iso-15288}. Each use case is instantiated in several difficulty tiers, from single operations to composed, realistic modeling flows such as fault correction, with faults injected into the model following Cibri\'an et al.\ \citep{cibrian2025validation} and Al-Shami et al.\ \citep{alshami2026faultloc}. The evaluation proceeds in two phases. First, the agent is benchmarked through the bare MCP bridge to establish a baseline. The collected failure data then drives the design of the harness, and the benchmark is repeated to measure the improvement. Every task has a ground truth, and the resulting model state is scored by an evaluator outside the agent loop \citep{wang2026pufibara}. Tasks are repeated to account for LLM non-determinism \citep{pradasgomez2026ductile}. Runs use Claude-family models. The outcome is a quantitative capability profile per use case and tier, before and after the harness, plus a qualitative failure taxonomy \citep{molinari2026engiai}.
