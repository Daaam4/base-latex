# Mitigating Hallucinations in SysML v2 Generation Using LLMs and a Tri-Layered Knowledge Graph Reasoning Framework

## Topic
Mitigating LLM hallucination in SysML v2 generation — invented or semantically incorrect model constructs — via a knowledge-graph-grounded prompting architecture, motivated by the general challenge of automating formal modeling with LLMs while preserving structural and semantic fidelity.

## Method
A tri-layered knowledge graph feeding reusable prompt templates: **Layer 1** (SysML Characterization KG) encodes reusable patterns/annotations for nine diagram types; **Layer 2** (Domain-Specific KG) extends Layer 1 with sector-specific constructs (aerospace, automotive); **Layer 3** (System-Specific KG) is auto-generated by parsing structured requirements and aligning them with Layers 1–2, then used to assemble system-level prompts and compile diagrams into a unified model. Case study: satellite system engineering. Evaluated against a manually curated ground-truth dataset (no verifiable dataset exists) on five metrics — Average Structure Score, Average Manual Structure Score, Average Semantic Score, Consistency Ratio, prompt-type analysis — assessing structural validity and semantic accuracy separately.

## Relevance
Framework produces structurally valid models reliably, but semantic fidelity and output determinism remain limited; capability-linked requirements plus structured prompting improve semantic accuracy/traceability. Motivates grounding the agent in the **live** model/tool state rather than a hand-built static KG — the thesis's semantic bridge queries MSoSA directly instead of maintaining a separate knowledge graph. Reference point for the *Erstellen* use case alongside `dehn2025nl2sysml`, `wu2025sysforge`, `bouamra2025systemp`; also echoes the field-wide call (shared with Fresemann, Bouamra, Quast) for better benchmarking tools and datasets.
