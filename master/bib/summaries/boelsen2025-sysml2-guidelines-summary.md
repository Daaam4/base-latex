# SysML v2 based modelling guidelines for mechanical system elements

**Tags:** #SysMLv2 #MBSE #ModellingGuidelines #MetadataDefinitions #Reuse #MechanicalEngineering

## Topic
The paper addresses the lack of standardized SysML v2 modelling guidelines for reusable mechanical system elements. It argues that because SysML v2 is a general-purpose, abstract modelling language, engineers currently model identical technical elements with different structures, which blocks reuse of system elements from model libraries and causes redundant modelling effort and error potential. Prior modelling guidelines exist only for SysML v1 and cannot be applied unchanged to v2's new textual notation and Definition/Usage-based metamodel; the paper's contribution is a first set of SysML v2-based guidelines for the mechanical domain, developed by selecting a suitable MBSE methodology (motego) and mapping its function/logic-level constructs onto native SysML v2 elements.

## Method
Four-step derivation: (1) elicit requirements a reusable-element guideline must satisfy (function-orientation with defined subfunction interfaces; a scope narrow-but-meaningful enough for reuse; parametric linking between abstraction levels); (2) survey and qualitatively score ten existing MBSE methodologies (motego, mecpro², Mechatronic Modeller, SPES, FAS4M, Integrated Product Model for Conceptual Design, SYSMOD, DC43, MagicGrid, OpenMBEE) against these requirements — motego is the only one fulfilling all three, so it is selected; (3) refine the requirements into eight concrete sub-requirements (functional decomposition and flow typing, solution-element definition via physical effect + active surfaces, domain-model/workflow integration, etc.); (4) specify SysML v2 notation/syntax for each requirement using custom **Metadata Definitions** (e.g. `SolutionElementDef`, `ActiveSurfaceDef`, `PhyEffectDef`) layered on native `PartDefinition`/`ConstraintDefinition`/`PartUsage` elements, worked through a concrete example — a lubricated mechanical rolling-contact element used in gear pairings and roller bearings, shown in both graphical and textual SysML v2 notation. No quantitative evaluation or benchmark is performed; validation is a single illustrative worked example, not measured against ground truth or multiple cases.

## Relevance
This is a concrete, worked precedent for encoding domain-specific modelling conventions natively in SysML v2 via Metadata Definitions rather than external profiles/OCL (the SysML v1 approach) — directly relevant to how a semantic MCP bridge could expose guideline-conformance as a tool-native check for the *Validierung* use case (checking that generated or edited elements conform to a metadata-defined structure). It also illustrates, at the notation level, exactly the kind of structural, function/solution-element modelling pattern an *Erstellen* (creation) task on a mechanical-domain benchmark item might require an agent to reproduce. The paper does not touch LLMs, agents, or evaluation methodology at all — its relevance is purely as a domain-modelling-convention reference, not as related work on AI capability or benchmarking.
