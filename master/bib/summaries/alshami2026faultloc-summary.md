# Automated Semantic Fault Localization in SysML v2: A Human-in-the-Loop Framework Using Knowledge-Graph Augmented LLMs

## Topic
The paper addresses semantic faults in SysML v2 models: engineering-domain violations (e.g. connecting incompatible physical interfaces, assigning inconsistent units) that pass SysML v2's compiler-like syntax validation but represent physically meaningless models. It positions itself against prior LLM-for-SysML-v2 work — Cibrián et al. (SysMLAgent, syntactic validity focus), DeHart (direct API editing), Qualis (tri-layer KG for generation, semantic scores still lag structural ones), Jin et al. (SysMBench corpus), Bouamra et al. (SysTemp templates) — arguing all of these leave the syntactic/semantic gap unresolved, and reframes the LLM's role from autonomous model *generation* to human-in-the-loop fault *localization and repair*.

## Method
A fine-tuned small language model (Qwen-2.5 Coder 1.5B, DeepSeek Coder 6.7B) coupled with a domain knowledge graph encoding physical compatibility rules (vehicle-domain interface adjacency + physical-quantity/unit constraints). A mutation engine synthesizes a dataset from 256 valid SysML v2 files (SysML v2 Pilot Implementation repo) via 12 syntactic and 5 KG-guided semantic mutation heuristics, yielding 8,301 labeled entries (5,497 syntax faults, 1,402 semantic faults, 1,402 correct examples); models are fine-tuned via LoRA to output unified-diff patches (or full repaired code, for comparison) rather than full rewrites. Evaluated on 1,184 held-out test samples with pass@1 and exact-match string comparison against ground truth: semantic fault repair improves from <3% (baseline, no fine-tuning) to >91% (fine-tuned, patch output), syntax repair reaches ~90% (full-code output) with patch-based output cutting output tokens by ~50–75% at a modest accuracy cost (patch vs. full-code: e.g. 91.9% vs. 95.7% semantic pass@1 for Qwen). Providing domain rules in-prompt without fine-tuning yields only marginal gains, showing fine-tuning — not prompting alone — is what internalizes the domain constraints.

## Relevance
Direct methodological precedent for this thesis's *Korrektur* use case: it operationalizes exactly the syntactic-vs-semantic fault distinction the thesis's fault-injection design needs, and demonstrates concretely that syntactic validity (compiler/tool-native checks) does not imply semantic correctness — the same gap the SEI blog post's worked example independently surfaces. Its mutation-operator taxonomy (Table 1: syntax/grammar, visibility/scope, type/units, logic/consistency, interface physics, quantity physics) is a ready-made checklist for designing fault-injection scenarios on the Apollo 11 model. Contrast point for the thesis: this paper repairs faults in isolated *text files* with a fine-tuned model and a hand-built domain KG, whereas the thesis's semantic bridge would ground correction in the *live* model state inside MSoSA rather than a static KG — reinforcing the thesis's live-tool/MSoSA differentiation argument already used against Qualis and the SEI work.
