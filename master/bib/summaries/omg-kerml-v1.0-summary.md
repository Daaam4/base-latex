## Topic
The normative OMG specification of the Kernel Modeling Language, the application-independent, formally-grounded modeling kernel that SysML v2 (and other domain-specific languages) is built on. It is not a research paper but a standards document: its "contribution" is defining a foundational language with well-grounded formal semantics for modeling systems, positioned explicitly as a base that more specific languages (like SysML v2) syntactically and semantically extend rather than duplicate. The specification frames itself against prior modeling standards (e.g. UML/SysML v1) by grounding semantics in mathematical logic and a self-describing Semantic Library, rather than relying on informal or externally bolted-on semantics.

## Method
As a normative specification, KerML has no empirical method; instead it defines a layered abstract/concrete syntax and semantics. Section 1 (Scope) and Section 6.1 (Language Architecture) describe three syntactic layers of increasing specificity: the **Root Layer** (elements, relationships, annotations, namespaces/packaging), the **Core Layer** (constructs with semantics based on classification, formally grounded in mathematical logic), and the **Kernel Layer** (commonly needed modeling capabilities such as associations, connectors, behaviors, functions, expressions, interactions, multiplicities, and metadata). Semantics beyond the Core Layer are given not by ad hoc rules but by the relationship of user-model elements to the KerML **Semantic Library**, itself expressed in KerML — meaning the full language is described as "simply a syntactic extension of the core, semantically extended using library models." Clause 2 (Conformance) defines four independent conformance levels a tool can claim: Abstract Syntax Conformance (CRUD + well-formedness validation against the metamodel), Concrete Syntax Conformance (textual notation CRUD, implies abstract), Semantic Conformance (demonstrable interpretation via execution/simulation/reasoning, implies abstract), and Model Interchange Conformance (import/export per the standard interchange format); every conformant tool must demonstrate at least Abstract Syntax and Model Interchange Conformance.

## Relevance
This is a foundational reference rather than related work to be positioned against, but it matters for the thesis on three concrete points. First, the conformance-level taxonomy (abstract syntax / concrete syntax / semantic / interchange) gives vocabulary for characterizing exactly what an MCP bridge into MSoSA is actually exposing when an agent calls a tool — e.g., whether a "create" or "patch" tool operates at abstract-syntax (structural CRUD, relevant to *Erstellen*/*Korrektur*) or claims semantic conformance (relevant to *Verifizierung*). Second, because KerML grounds constraints and classification semantics in formal mathematical logic rather than external formalisms, it underpins why SysML v2 range-based constraints can be verified natively as constraint-satisfaction problems (as used by Ratzke et al. and referenced alongside Boelsen's guideline work) instead of requiring transformation to an external tool, which is directly relevant to how the thesis's *Verifizierung* use case could be operationalized inside MSoSA. Third, it is the authoritative source for the Root/Core/Kernel layering and the metamodel scale (400+ elements, matching the count cited by Bazzal et al. when motivating why MCP tool design must split across multiple servers) that the thesis's design chapter needs to reference precisely rather than approximate from secondary sources.
