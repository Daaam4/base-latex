# Ensuring Semantic Consistency in SysML v2 Models Through Metamodel-Driven Validation

**Tags:** #SysMLv2 #MetamodelValidation #Verification #ANTLR #ToolLandscape

## Topic
The paper addresses the lack of comprehensive, standardized validation for SysML v2 models: existing tools (SysIDE, SysON, Cameo Systems Modeler, SysMD, SAVVS) each cover only part of the syntax/semantics space, are tied to specific representations, or depend heavily on user configuration. Its core claim is a systematic, metamodel-driven validation method that derives validation rules directly from the official SysML v2 metamodel (beta 2) rather than from superficial, implementation-dependent syntax checks, covering both structural (syntactic) and semantic inconsistencies uniformly. It positions itself against prior SysML v2 work (Molnár et al.'s formal verification survey, Sultan & Apvrille's AI-driven consistency checks, Thorburn et al.'s lightweight formal-methods integration) as narrower in scope or reliant on external formalisms rather than a complete metamodel-grounded strategy.

## Method
The method extracts formal schemas (valid attributes, types, enum values per element) programmatically from the SysML v2 metamodel documentation, then runs a four-step pipeline — lexical validation, ANTLR-based syntax validation (SysML v2 grammar/lexer/parser generating an AST), semantic validation (tree traversal checking cross-references, uniqueness, cardinality), and an "on-the-fly" fixing/suggestion step using Levenshtein distance to recommend corrections for misspelled attribute names — applied to both JSON-serialized and native SysML v2 textual files. Evaluated on 25 models (aerospace, automotive, software-development domains) drawn from the OMG's official SysML-v2-Release test-case repository, with 428 syntax/semantic errors deliberately and randomly injected into 20 of the 25 models (5 left clean as a control). Result: 97% mean detection rate across the SyE (Syntax Error) and SeE (Semantic Error) ratios, near-perfect on syntax errors (undetected residual cases limited to duplicate attributes on the same element) and slightly lower but still robust on semantic errors (cardinality, UUID uniqueness, cross-model reference resolution); validation time scales roughly with model count but stays under ~300 s for most instances. No direct comparison to other tools was possible because those tools do not report equivalent error-count metrics or are not openly accessible/reproducible.

## Relevance
This is a **Verification**-type paper (confirmed by the project's own iso-15288 audit, 19.09.2026): it performs metamodel-conformance checking — syntax, cardinality, cross-reference integrity — not behavioral simulation or stakeholder-objective fulfilment, and the paper itself contrasts its static, structural approach against simulation-based tools like SysON. For the thesis, it is a concrete precedent for the **Verifizierung** use case: it supplies (1) a syntax/semantic error taxonomy and a random fault-injection methodology (428 errors across 20/25 models) that is methodologically close to this thesis's own fault-injection design for **Korrektur**, and (2) a quantitative detection-rate metric (97%, split into SyE/SeE ratios) as a comparison point for what "good" syntactic/semantic validation coverage looks like. It also documents that no comparable open, reproducible SysML v2 validation baseline exists — reinforcing this thesis's benchmark-gap argument — and its explicit conflation of "semantic validation" with structural/cross-reference checks (rather than true stakeholder-level validation) is a useful cautionary example for keeping the thesis's Verifizierung/Validierung distinction sharp.
