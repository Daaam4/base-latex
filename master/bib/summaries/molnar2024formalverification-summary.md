# Towards the Formal Verification of SysML v2 Models

## Topic
The paper, authored by members of the OMG Systems Modeling Community's Formal Methods Working Group, argues that SysML v2's new formal semantics (grounded in KerML's first-order-logic ontology and its Root/Core/Kernel layering) make it substantially more amenable to formal methods than SysML v1, which lacked precise semantics and suffered from poor tool interoperability. Its core contribution is a survey of five concrete tool integrations — SysMD, Monterey Phoenix (MP-Firebird), Gamma, Imandra, and SAVVS — each applying a different formal-methods technique (constraint propagation, exhaustive trace generation, statechart model checking, automated theorem proving, contract-based safety analysis) to SysML v2 models, plus a proposed unified workflow for representing verification/analysis tasks and their results natively as SysML v2 elements (using the language's built-in "analysis case" and "verification case" constructs).

## Method
This is a tool/workflow survey and position paper, not an empirical evaluation: it explains each tool's mapping from SysML v2/KerML constructs to its own formal backend (e.g., Gamma → XSTS → UPPAAL/Theta/Spin/nuXmv model checkers; SAVVS → OCRA/nuXmv/xSAP; Imandra → a SysML-v2-to-IML transpiler feeding an OCaml-based automated reasoner), summarized in two comparison tables of supported techniques (model checking, theorem proving, contract-based design, fault injection, back-annotation, state-space diffing, etc.) and supported language elements (state machines, requirements, verification cases, etc.). It illustrates the proposed workflow with four small worked examples (a Tank volume-requirement model, a two-state LightSwitch state machine, a traffic-light model with 174 invariant behavior regions, and a redundant-sensor fault-tree example) but reports no quantitative benchmark, no ground truth, and no comparison against a baseline — the explicit framing throughout is "work in progress" while SysML v2 was still being finalized. It also notes, in passing, that Imandra's transpiler is being used to power a "hallucination-free" LLM interface for answering natural-language questions about SysML models via automated reasoning, though this is mentioned only as an application example, not evaluated.

## Relevance
This paper substantiates the *Verifizierung* use case's ISO 15288 framing used in the thesis: every technique surveyed here (model checking, theorem proving, SMT/contract-based refinement, fault injection against formally stated properties) is conformance-checking against a formal specification — none performs behavioral simulation against stakeholder/business objectives (ISO-Validation), consistent with the thesis's audited verdict that this paper is Verification, not Validation, despite using both terms informally. It gives the broadest landscape of *native* formal tooling around SysML v2 available in the literature, useful as the state-of-the-art backdrop against which an MCP-bridge agent's Verifizierung capability (checking a requirement/constraint on the live model) can be positioned: unlike these five specialist tools, an LLM agent through MSoSA would perform ad-hoc, prompt-driven verification without a dedicated formal backend, trading rigor for flexibility and accessibility. The passing mention of an LLM+automated-reasoning interface on top of Imandra is a small but relevant data point for the "LLM as interpretive layer over formal SysML v2 semantics" framing shared with DeHart's founding paper, though it is not elaborated or evaluated here.
