name: qualify-paper
description: Vet and file a candidate source for the Master's thesis (branch master-thesis) — check relevance, reformat its summary, and wire it into the mind map / quellen.bib / bib/papers. Use when the user assigns a paper (a "todo - sources/*.md" file, or a paper name/PDF) to qualify/review/add.
---

Given one source (a `master/todo - sources/*.md` summary file, and/or a paper name or PDF), do this — one paper per pass, lightweight, no re-litigating already-settled sources:

1. **Relevance check.** Read the summary file (or the paper itself if no summary exists yet). Cross-check `master/todo - sources/0. Index.md` — is it already listed there (theme row, "Quick reference by theme" table, TOP 3, or the "proposed ~15" list)? If it clearly serves one of the five use cases (Abfragen/Validierung/Verifizierung/Korrektur/Erstellen), a competing-work/methodology-sibling role, or a named gap-citation — **relevant**. If it's redundant, off-topic, or wrong SysML version/domain with no stated role — **tell the user to remove it, do not proceed**.
2. **Reformat the summary** (only if it doesn't already match): header line + `**Bib:**`/`**Type:**`/`**Verified:**`, `**Metadata:**`, `**Tags:**`, then `## Topic` / `## Method` / `## Relevance` / `## Status`. Use `master/bib/summaries/dehart2024llm-summary.md` as the reference template. Drop long section-by-section outlines into these four sections — don't keep the old headings.
3. **File the summary into `master/bib/summaries/`** — but only for **Type 1 scientific** sources (papers/standards that get or already have a PDF in `bib/papers/`). Type 2 blogs and Type 3 repos stay in `master/todo - sources/` (they don't have a 1:1 PDF to pair with). Mint the bibkey now if one doesn't exist yet (same key you'll use in step 5). Move the reformatted file from `master/todo - sources/<name>.md` to `master/bib/summaries/<bibkey>-summary.md` — filename is the **bibkey**, not the old descriptive slug, so it matches the eventual `bib/papers/<bibkey>.pdf`. **If a summary for this source already exists under `todo - sources/` — even one that already matched the format in step 2 and needed no reformatting — remove it from there as part of this step; never leave a copy in both places.** Use `git mv` (rename in place), not copy-then-delete. If the PDF isn't found yet (step 4 pending), still file the summary here now and note `PDF pending` in its `## Status` — don't leave it parked in `todo - sources` waiting for the PDF.
4. **Locate and file the PDF.** Check `~/Downloads` (match by title words or arXiv/DOI id, prefer most-recently-added). If not found, say so explicitly and stop after steps 1–3 — don't block the rest of the workflow, but flag `PDF pending` in both the summary's `## Status` and the bib `note`. Once found: `mv` it to `master/bib/papers/<bibkey>.pdf`.
5. **Promote the bib entry.** Check `master/bib/pool-verified.bib` first — a verified entry usually already exists there; reuse it verbatim (don't re-derive metadata). Insert into `master/bib/quellen.bib` in the matching `% ---------- Subject N: ... ----------` block (create a new block only if none fits — e.g. "Agent evaluation & tooling benchmarks" for adjacent-domain agent papers). Point the `note`'s PDF path at `bib/papers/<bibkey>.pdf`.
6. **Add to the mind map** (`master/bib/mindmap.md`). Insert under the correct existing leaf/node (CRUD Operations sub-case, Verification/Validation, MCP, AI Harness, EvalFW node level for taxonomy/methodology papers, etc.) — follow the theme mapping in `0. Index.md`'s "Quick reference by theme" table. Keep it in the same terse, cross-referencing style as neighboring entries (what it adds, how it relates to/contrasts with what's already there).

Never invent metadata — everything must trace to Crossref/arXiv/the PDF or an already-verified `pool-verified.bib` entry. Don't touch `0. Index.md` unless the source is genuinely new to it (most assigned papers are already indexed; just fill in the artifacts above). Do all steps for one paper before moving to the next.
